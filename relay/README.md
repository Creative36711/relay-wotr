# Как запустить пульт транспорта

Коротко: пульт — это небольшой сервер, который вы запускаете у себя на
компьютере одной командой и открываете в браузере. Это не десктопное
приложение, ставить ничего не нужно, кроме Node.js.

---

## Что нужно один раз

**Node.js 20 или новее.** Проверить: в терминале набрать `node -v` и нажать
Enter. Если видите версию `v20…` или выше — всё есть. Если «команда не найдена» —
скачать с [nodejs.org](https://nodejs.org) кнопкой LTS и установить как обычную
программу.

## Шаг 1. Скачать репозиторий

Терминал (на Windows — «Git Bash» или PowerShell) и две команды:

```bash
git clone https://github.com/Creative36711/relay-wotr.git
cd relay-wotr
```

Нужна папка `relay/` — в ней вся служба. Если `git` не установлен, можно скачать
архив с GitHub (кнопка **Code → Download ZIP**), распаковать и перейти в
распакованную папку.

## Шаг 2. Посмотреть пульт без настройки

Так вы увидите интерфейс сразу, ничего не подключая. Состояние будет
демонстрационным: оно живёт в памяти и исчезает после остановки.

```bash
cd relay
RELAY_DEMO=1 node src/index.mjs
```

В терминале появится строка `Транспорт слушает http://0.0.0.0:8787`.
Откройте в браузере **http://localhost:8787** — это и есть пульт.

Остановить: `Ctrl+C` в терминале.

В пульте сверху есть короткий статус и безопасное следующее действие. После
нажатия кнопки пульт явно показывает, что именно он отправил и подтвердил.
Если Admin или ScriptCat удерживает ход из-за незавершённого локального
состояния, повторный «Шаг» блокируется: используйте **«Скопировать диагностику»**
и отправьте отчёт сопровождающему. Ожидание не очищается автоматически.
Отчёт маскирует типичные токены и email, но перед отправкой всё равно проверьте
текст: в событиях могут быть рабочие детали проекта.

## Шаг 3. Подключить настоящую книгу

Демонстрация показывает интерфейс, но не помнит ничего. Чтобы состояние
сохранялось, службе нужен доступ к книге. Есть два пути, и короткий — первый.

### Путь А (короткий): мост в книге. Ключ Google не нужен

Один файл кладётся **внутрь** таблицы, и дальше доступ даёт он сам: никакой
консоли Google, никакого JSON-ключа, никакого «добавьте робота в редакторы».

1. Откройте книгу «Relay · WOTR — состояние транспорта» (она лежит в папке
   **Arena** на Google Drive) → **Расширения → Apps Script**.
   Это **не** проект `Gateway` из той же папки: Gateway умеет только файлы
   (логи, payloads) и книгу не читает. Мост нужен свой, привязанный к таблице.
2. Удалите то, что там есть, и вставьте целиком файл
   **`relay/apps-script/Code.gs`**.

   Файл носить руками не обязательно: при запущенном транспорте откройте
   **http://localhost:8787/api/mount** — там тот же код, кнопка «Скопировать»,
   короткий порядок шагов и проверка связи с мостом.
3. В самом верху замените строку `ЗАМЕНИТЕ-ЭТУ-СТРОКУ-НА-СВОЙ-КЛЮЧ` на любую
   длинную случайную строку. Это пароль моста, придумайте его сами.
4. **Один раз дайте мосту право на внешний HTTP:** в редакторе выберите
   функцию `authorize` и нажмите **Запустить** — Google спросит разрешение
   (`script.external_request`), нажмите **Допустить**. Без этого шага действие
   `notion` (запросы к Notion через мост) отвечает «У вас нет разрешения на
   вызов функции UrlFetchApp.fetch»: веб-приложение не умеет само показывать
   окно авторизации.
5. **Развернуть → Новое развёртывание → тип «Веб-приложение»**.
   «Запуск от имени» — **Я**, «У кого есть доступ» — **Все**. Скопируйте адрес
   вида `https://script.google.com/macros/s/…/exec`.
6. Вставьте адрес и ключ на странице **http://localhost:8787/api/mount** —
   в поля «Адрес веб-приложения» и «Ключ моста», затем **«Сохранить и
   проверить»**. Служба сама запишет настройку рядом с собой и сразу
   проверит связь: скажет, сколько листов видит. Перезапускать не нужно.

   Файл `relay/bridge.txt` при этом создаётся сам — открывать его и что-то
   дописывать не надо. Идентификатор развёртывания в поля не вставляется: он
   служит для обновления развёртывания, а доступ даёт адрес `/exec` (он уже
   содержит идентификатор внутри).

Запустить: двойной клик по `relay\Запустить транспорт.bat`. Если `bridge.txt`
уже есть, файл скажет «Вход в книгу: мост Apps Script» и не станет искать ключ
Google. Если его нет, батник спросит адрес и ключ прямо в окне запуска — это
то же самое, что вставить их на странице.

**Почему «Все», а не «Только я».** Веб-приложение открыто интернету, поэтому
ключ в `Code.gs` и есть защита: без него мост ничего не читает и не пишет.
С «Только я» транспорт получил бы страницу входа вместо данных.

**Чего у моста нет.** Он ходит к книге по одному запросу за операцию, поэтому
на больших журналах медленнее прямого Sheets API. Для книги этого размера
разница незаметна; для сотен строк в «Событиях» — уже заметна.

### Путь Б: ключ сервисного аккаунта (если мост не подходит)

Даёт прямой доступ к Sheets API и работает быстрее, но настройка длиннее:
проект в Google Cloud, включение Sheets API, ключ JSON, роль редактора книги.

1. Откройте [console.cloud.google.com](https://console.cloud.google.com) и
   создайте проект (или возьмите существующий).
2. В поиске сверху наберите **Google Sheets API** → **Enable**.
3. Меню **APIs & Services → Credentials → Create credentials → Service
   account**. Имя любое, например `relay`. Роль не нужна.
4. Откройте созданный аккаунт → вкладка **Keys** → **Add key → Create new key
   → JSON**. Файл скачается сам. Положите его рядом с папкой `relay/` и
   назовите `sa.json`.
5. Откройте `sa.json` любым редактором и найдите строку `"client_email"` — там
   будет адрес вида `relay@проект.iam.gserviceaccount.com`. Скопируйте его.
6. Откройте книгу → **Настройки доступа → Добавить пользователей** → вставьте
   этот адрес → роль **Редактор** → Отправить.

Файл запуска найдёт `sa.json` сам: он ищет `..\sa.json`, `sa.json` рядом с
собой и любой `*.json` с `client_email` в этих папках.

Те же две переменные вручную:

```bash
cd relay
RELAY_SPREADSHEET_ID=вставьте_код_книги \
RELAY_GOOGLE_SA_FILE=../sa.json \
node src/index.mjs
```

PowerShell:

```powershell
$env:RELAY_SPREADSHEET_ID="вставьте_код_книги"
$env:RELAY_GOOGLE_SA_FILE="..\sa.json"
node src/index.mjs
```

Командная строка (`cmd`) — **немного иначе**: `set "ИМЯ=значение"`, кавычки
вокруг всей пары, а не вокруг значения. Иначе пробел в пути обрежет значение.

```bat
cd relay
set "RELAY_SPREADSHEET_ID=вставьте_код_книги"
set "RELAY_GOOGLE_SA_FILE=..\sa.json"
node src\index.mjs
```

### Что остаётся токенами, а что нет

- **Notion** — токен, который вы получаете сами. Вставляется **в пульте**, в
  поле «Токен Notion», и проверяется сразу: служба ответит, сколько баз видит.
  Перезапускать транспорт не нужно. Принятый токен служба кладёт в
  `notion-token.txt` рядом с `bridge.txt` (права600, в репозиторий не идёт) —
  при следующем запуске ввод не нужен, служба печатает
  «Токен Notion: из notion-token.txt». Переменная `NOTION_TOKEN` остаётся
  старшим путём для тех, кто запускает службу скриптом.

  Без справочника ролей цикл **работает**: роль и функция берутся из строки
  очереди, адрес агента — из листа «Экземпляры». Справочник уточняет раскладку
  (репозиторий роли, её готовность), поэтому он полезен, но не обязателен.
- **GitHub** — токен, тоже ваш. Нужен только для приватного репозитория.
- **Google** — при пути А не нужен вовсе; при пути Б это ключ робота.

## Шаг 4. Проверить, что живо

Откройте **http://localhost:8787/api/health**. Ответ вида
`{"ok":true,…,"demo":false}` значит, что служба видит книгу. Если
`"demo":true` — книга не подключилась, смотрите сообщение в терминале.

## Что где лежит

| Что | Где |
|---|---|
| Пульт (страница) | `relay/web/` — открывается службой, отдельно не запускается |
| Служба (решения, очередь, слоты) | `relay/src/` |
| Тесты службы | `relay/tests/` — запуск `npm test` из папки `relay` |

## Частые ошибки

**`RELAY_SPREADSHEET_ID не задан`** — служба не знает, где хранить состояние.
Это не поломка: задайте код книги или запустите с `RELAY_DEMO=1`.

**`Нет доступа к книге`** — служба не нашла ключ сервисного аккаунта. Задайте
`RELAY_GOOGLE_SA_FILE=путь/к/ключу.json` (или `RELAY_TOKEN`).

**`403 … The caller does not have permission`** — книга не расшарена на адрес из
ключа. Откройте `sa.json`, скопируйте `client_email` и добавьте этот адрес в
доступ к книге как **Редактора**. Это самая частая ошибка, и она не про код.

**Порт занят** — другой процесс уже слушает 8787. Задайте другой:
`PORT=8788 node src/index.mjs` и откройте `http://localhost:8788`.

**Мастер пишет «не всё найдено»** — смотрите на знак. `✓` сделано, `!`
замечание (цикл работает, что-то можно улучшить), `✕` отказ. Если единственный
`✕` — `notion.rolesDb`, это не поломка: вставьте токен Notion в поле выше, и
справочник появится.

**«до Notion не дозвонились (ECONNRESET)»** — это сеть, а не токен. На пульте
есть кнопка **«Проверить сеть»**: она стучится в `api.notion.com` без токена и
называет код отказа, по которому видно, что чинить:

| Код | Что это | Что делать |
|---|---|---|
| `ECONNRESET` | соединение оборвал прокси или фильтр | укажите прокси при запуске или выключите фильтр |
| `UNABLE_TO_VERIFY_LEAF_SIGNATURE` | подмена сертификата антивирусом или прокси | отключите проверку HTTPS в антивирусе или добавьте исключение |
| `ENOTFOUND` | имя не разрешилось | DNS или VPN |
| не ответил за 30 с | запрос не доходит | VPN, прокси, фильтрация |

Токен перевыпускать не нужно: он тут не при чём.

**Notion необязателен.** Роли читаются из листа **«Роли»** в книге. Кнопка
**«Роли в книгу»** переносит их туда из Notion один раз; после этого цикл живёт
на одной книге, и недоступный Notion ничего не ломает. Лист можно заполнить и
руками: `Роль`, `Функция`, `Статус`, `Agent URL`, `Репозиторий`.

**«Проверить сеть» вместо догадок.** Одна кнопка проходит по звеньям — DNS, порт
IPv4/IPv6, TLS (с отпечатком сертификата), ответ Notion, адрес книги — и ставит
✕ там, где обрыв. Там же видно, что ответил Notion дословно.

**«Замерить книгу»** показывает, сколько стоят чтение и запись и сколько
времени займёт один шаг: мост к Apps Script ходит по одному запросу за
операцию, поэтому на большой книге шаг дольше.

**Ничего вводить про сеть не нужно.** Служба не спрашивает прокси: если он
задан в системе (`HTTPS_PROXY`), запуск сам включает его для Node — на этом всё.
Всё, что нужно знать про сеть, показывает кнопка **«Проверить сеть»** в пульте:

- **Notion и книга отвечают** — сеть в порядке, дальше только токен и доступ.
- **Книга отвечает, Notion нет** — интернет есть; Notion режется отдельно
  (фильтр по домену, VPN-правило, антивирус). Токен тут не при чём.
- **Ничего не отвечает** — нет исходящего соединения вообще.

**«Notion вернул не данные: страница фильтра или капча (сервер: …)»** — запрос
дошёл, но ответил не Notion. Так делает VPN-клиент (HAPP, Xray, «умный» режим),
антивирус с проверкой HTTPS или фильтр по домену. Токен при этом рабочий:
менять его не нужно, нужно поменять маршрут. В сообщении назван `server` из
ответа — по нему видно, кто именно вмешался.

**Вход в Notion в браузере не нужен.** Токен — это отдельный ключ интеграции,
а не сессия вкладки: служба ходит в Notion сама, без браузера. Поэтому «не
залогинен в Firefox» на работу не влияет. Важно другое — доступ: страницу
проекта нужно открыть для интеграции (в Notion: `…` → **Соединения** →
добавить интеграцию).

**Открывается, но пусто** — в книге нет листа «Экземпляры». Служба создаёт его
сама при первом обращении, если у токена есть право на правку книги. Если права
только на чтение — лист нужно добавить вручную с шапкой из `relay/src/schema.mjs`.

## Куда это потом придёт

Сейчас пульт — это страница, которую вы открываете сами. После появления
клиента протокола во вкладке (следующий шаг) вкладки начнут забирать работу у
службы, и пульт станет единственным интерфейсом вместо панели ScriptCat. Пока
этого нет: панель ScriptCat работает как раньше, а служба живёт рядом и не
мешает.
