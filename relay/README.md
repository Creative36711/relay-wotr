# Relay · WOTR — служба транспорта

С 1.19.0 (D-009) служба принимает решения: очередь, выдачи, слоты, квоты, журнал
и пакет инцидента. Здесь же пульт, который должен заменить интерфейс ScriptCat.

> **Что работает сейчас, а что нет.** Служба проверена своими тестами и пультом,
> но **клиента протокола в вкладке ещё нет**: `tools/script-cat/src/**` читает
> очередь из `GM_setValue` по-прежнему. Значит живой цикл пока идёт прежним
> путём, а службу никто не спрашивает — она ничего не ломает, но и не ведёт ход.
> Панель ScriptCat поэтому остаётся на месте до того же коммита, который принесёт
> клиента. Подробности — D-009, пункты 6–7.

## Зачем это отдельно от вкладки

Прежняя модель держала очередь в памяти одной вкладки. Отсюда три боли, которые
владелец и просил убрать:

1. **Две вкладки не видели друг друга.** Очередь и ожидание жили в
   `GM_setValue` — локально для окна.
2. **Одновременно могла идти одна карточка.** Единицей работы была вкладка, а
   не строка работы.
3. **Разбор поломки начинался с нуля.** Журнал был кольцевым буфером на 200
   строк и не содержал действий человека.

Служба решает это устройством, а не настройкой: состояние в Google Sheets,
единица работы — строка очереди, журнал общий.

## Запуск

```bash
RELAY_SPREADSHEET_ID=<id книги> \
RELAY_TOKEN=<токен Google с доступом к Sheets> \
node src/index.mjs
```

Пульт открывается на `http://<host>:8787/`. Переменные:

| Переменная | Зачем |
|---|---|
| `RELAY_SPREADSHEET_ID` | книга состояния; без неё служба не стартует (кроме демо) |
| `RELAY_TOKEN` | токен Google |
| `RELAY_TOKEN_CMD` | команда, печатающая токен (если токен обновляемый) |
| `NOTION_TOKEN` | нужен только мастеру настройки: он ищет базы |
| `PORT`, `HOST` | по умолчанию `8787` и `0.0.0.0` |
| `RELAY_DEMO=1` | состояние в памяти: посмотреть пульт, ничего не настроив |

## Протокол вкладки

Вкладка не решает ничего и знает шесть действий:

| Действие | Смысл |
|---|---|
| `hello` | «я вкладка такого-то аккаунта» → служба называет слот |
| `pull` | «дай работу» → выдача или «жди» с причиной |
| `beat` | «я жива» → продлить выдачу, сказать, чего жду |
| `report` | «прочитала ответ» → разбор маркера и результат |
| `event` | «вот что случилось» → строка в общий журнал |
| `bye` | «вкладка уходит» |

Ответ на `pull` всегда один из трёх: работа, «жди» с причиной, «тебе сюда
нельзя». Третий — не ошибка вкладки, а расхождение раскладки, и он называет
причину словами.

## Что служба не делает

Она не открывает вкладки, не нажимает кнопки и не переключает контейнеры:
этого не умеет ничто, кроме человека и самой вкладки. Максимум — сказать
вкладке «твоя работа вот она» и ждать отчёта.

Она также не выставляет `Accepted`: это решение Coordinator'а. Транспорт
фиксирует факт — прочитан ответ или нет.

## Проверки

```bash
npm test          # 59 тестов службы: диспетчер, служба, инцидент, настройка, HTTP
```

Тесты, которые важнее остальных:

- `dispatch-async.test.mjs` — несколько карточек одновременно, ход возвращается
  тому, кто закончил, предел соблюдается, лимит аккаунта выключает слот;
- `service-flow.test.mjs` — шаг действительно выдаёт, повторный `pull` узнаёт
  свою выдачу, чужой run id даёт разбор с пакетом;
- `incident-package.test.mjs` — в пакете есть дорожка человека, живые выдачи и
  проверка «чей это run id»;
- `setup-and-settings.test.mjs` — **в расширенных настройках нет ничего, без
  чего цикл не работает** (инвариант, а не пожелание).
