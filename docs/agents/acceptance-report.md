# ScriptCat project adaptation · acceptance record

Operational acceptance is generated by the current full gate and recorded per release in
`docs/evidence/scriptcat-<version>.md`; the last release cut from this repository is `1.16.8`
(`docs/evidence/scriptcat-1.16.8.md`, внешний D-021). From the transport split onward the gate and the release
note run in `Creative36711/relay-wotr`, while the mission, the card and the acceptance decision stay here.
Historical upstream release evidence is frozen under
`tools/script-cat/upstream-fixtures/docs/agents/acceptance-report.md` (transport repository); it is test
evidence, not project process authority.

Required commands — run them from a checkout of `Creative36711/relay-wotr`, never from this repository: the
`scriptcat:*` and `test:scriptcat*` aliases were removed from `package.json` here, so `npm run scriptcat:check` in
Open BFME can only answer `Missing script`. Record the `relay-wotr` commit SHA and the project card ID in the
same report.

```bash
npm run scriptcat:check
npm run scriptcat:guard
npm run test:scriptcat
npm run test:scriptcat:regression
npm run test:scriptcat:tool-limit
```

The accepting report records tested SHA, Node version, command return codes, test/pass/fail totals, bundle SHA-256, version/runtime equality, build fingerprint, digest version and portability result. A browser live cycle is a separate manual gate before enabling auto mode; repository tests do not claim that the userscript was installed.
