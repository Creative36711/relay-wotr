# ScriptCat — журнал выпусков транспорта

Сейчас пульт Relay — **1.34.5**, ScriptCat — **1.35.2**, Firefox add-on — **0.1.4**; локальная адаптация userscript основана на upstream 1.16.1. С 1.19.0 цикл ведёт служба `relay/`, а вкладка — исполнитель и мост к Arena/Notion (D-009). Версия пульта описывает запущенный Node-процесс; версия ScriptCat — установленный userscript, они обновляются отдельно.

## Выпуск 1.35.3 (D-036) · ScriptCat 1.35.3 · отправка и маркер в фоновой вкладке

Симптом с пульта: промпт введён, плашка убрана, а сообщение не уходит, пока
Мастер сам не переключится на вкладку; маркер Координатора приходит, но цикл
«не двигается». Firefox режет таймеры фоновой вкладки — сначала до секунды,
а через пять минут до одного пробуждения в минуту, — и короткие дедлайны
отправки истекали до первой проверки.

1. **Весь путь отправки терпит в фоне:** `pollWait`, `ensureComposer`,
   `waitForSendReady`, `waitSendReady`, `waitSent`, `captchaGuard` и
   `clickReady` растягивают дедлайн через общий `patience` (минута в фоне,
   втрое для длинных) — то, что уже делали ожидания PR-ветки.
2. Маркер плана принимается по тику цикла (15 с на экране, до минуты в
   фоне); с менеджером 0.1.4 вкладка выводится на передний план при ходе и
   при `expect:plan`, так что в штатном сценарии обработка идёт на экране.
3. Релиз: ScriptCat 1.35.2 → 1.35.3 (пульт и add-on не менялись).

## Relay 1.34.5 · подробная проверка сети и видимая ошибка диагностики

`/api/net-deep` раньше завершался `ReferenceError` при сборке поля `ok`
(использовалась несуществующая переменная `failed`). Пульт игнорировал HTTP
ошибку и показывал пустое «обрыв найден». Теперь результат формируется из
проверенных шагов, а пульт показывает серверную ошибку, если отчёт не пришёл.
После обновления и перезапуска Relay проверка отображает строки DNS, TCP,
TLS, прокси, ответа Notion и книги с точным местом обрыва.

## Firefox add-on 0.1.4 · фокус уже принятого, но незавершённого плана

Если Relay уже подтвердил планирующий ход и очистил `turnRequest`, но
ScriptCat всё ещё держит локальный `expect:plan`, менеджер всё равно выводит
Admin-окно и Arena-вкладку на передний план. Это также срабатывает при первой
проверке после обновления/перезапуска менеджера. Фокус одноразовый для одного
ожидания и сбрасывается после его завершения, чтобы следующий план в той же
вкладке тоже мог привлечь внимание.

## Firefox add-on 0.1.3 · убрать неподдерживаемое permission

В Firefox manifest schema нет permission-строки `windows`, поэтому 0.1.2
выдавал предупреждение при загрузке. Удалена только эта строка: вызов
`browser.windows.update()` оставлен, он не требует такого токена permission
в Firefox. Проверка манифеста теперь отдельно запрещает его возвращение.

## Firefox add-on 0.1.2 · фактический foreground-переход для планирующего хода

При новом запросе Координатора менеджер теперь явно выводит на передний план
не только Arena-вкладку, но и её окно Firefox. Раньше `tabs.update({active:true})`
мог выбрать вкладку в другом окне, не переключив само окно: страница оставалась
фоновой, и Arena/браузер могли отложить отправку или таймеры. Успех фокуса
фиксируется только после обоих вызовов; при ошибке следующий опрос повторит
попытку, а ошибка появится в статусе менеджера. Автоматическое привлечение
вкладки происходит один раз на ID хода, без повторного перехвата фокуса.

Обновите/перезагрузите временный add-on в Firefox. Реальное поведение
переключения зависит от Firefox и требует проверки в целевом профиле; live
операционный цикл этой правкой не запускался.

## Выпуск 1.35.2 · граница роли и устойчивый claim планирующего хода

1. Координатор назначает Executor/Auditor по Scope и Function; worker Status,
   Agent State и Agent URL больше не являются условиями планирования. Relay
   выбирает слот и аккаунт с учётом квоты и создаёт недостающую пару роль×слот.
2. Планирующий turn подтверждается, когда ScriptCat записал локальное
   ожидание/отправку/переход. Пока запрос длится, локальный owner продлевает
   короткий claim; `claimed: false` больше не должен появляться из-за обычного
   таймаута Google-транспорта при активном `expect:plan`.
3. Arena delivery подтверждается собственным marker/expect flow, отдельно от
   того, что Relay передал локальный планирующий ход.
4. Релиз: ScriptCat 1.35.1 → 1.35.2; Node Relay и Firefox add-on не менялись.

## Выпуск 1.35.1 · старт Coordinator после синхронизации credentials

1. После перехода на страницу роли первый `hello` к Relay завершается до
   исполнения отложенного ручного шага. Это предотвращает гонку, в которой
   новая Arena-страница начинала запрос миссии до загрузки Relay-owned Notion
   token в память вкладки. Если credentials ещё недоступны, шаг не запускается.
2. Ошибка чтения списка миссий в Notion больше не маскируется под «активной
   миссии нет»: причина попадает в журнал, token redacted, запрос Coordinator
   остаётся доступен для безопасного повтора.
3. Физический фокус браузера выполняет Firefox add-on, не userscript.
   Начиная с 0.1.1 он активирует admin/Arena-вкладку один раз на новый ID
   планирующего хода; проверьте, что обновлён именно add-on, если пульт остался
   на переднем плане. Повтор хода не крадёт фокус.
4. Релиз: ScriptCat 1.35.0 → 1.35.1; Node Relay 1.34.3 → 1.34.4.

## Выпуск 1.35.0 (D-035) · ScriptCat 1.35.0 · Firefox add-on 0.1.1

1. **Ход из пульта больше не упирается в удержание переключения.** Симптом:
   служба передавала планирующий ход каждые 15 секунд («вкладка получила
   ход» → «повторится: вкладка пока не создала ожидание»), а вкладка отвечала
   «Проект ждёт ручного запуска после переключения» и ничего не делала.
   Удержание снимают только кнопки вкладки, а новые ходы приходят из пульта —
   вечный цикл. Теперь ход Координатора и выдача работы из очереди снимают
   удержание: это явное действие Мастера. Локальные отложенные шаги удержание
   по-прежнему ждут.
2. **Переключение проекта из пульта снова ставит удержание.** Сеттер потерян
   при переносе переключения в пульт; без него отложенный шаг старого
   профиля выполнялся бы в новом после перезагрузки. Первый «Шаг» из пульта
   (или «Включить») удержание снимает.
3. **Менеджер Firefox показывает admin-вкладку при новом планирующем ходе:**
   один фокус на id запроса, без воровства внимания на повторах. Фоновая
   вкладка к тому же экономит таймеры ScriptCat.
4. Подсказка очереди обратной связи теперь ведёт на «Шаг» пульта — локальной
   кнопки «Шаг» в панели больше нет.
5. Релиз: ScriptCat 1.34.4 → 1.35.0; Firefox add-on 0.1.0 → 0.1.1
   (пульт не менялся).

## Выпуск 1.34.4 (D-034) · ScriptCat 1.34.4

1. **Допуск проекта больше не требует «Agent URL» у рабочих ролей.** После
   D-015 адрес рабочей роли живёт в листе «Экземпляры» (пара роль + слот) и
   появляется там, когда агента создаёт сам транспорт; пустое поле в «Ролях»
   — норма. Раньше проверка из пульта падала на первой такой роли («некорректный
   Agent URL») и блокировала включение проекта, хотя системе от строки ничего
   не нужно. Заполненный URL по-прежнему проверяется строго: домен, страница
   `/agent/…`, уникальность.
2. **Переход к роли с пустым URL разрешён.** `projectRoleAllowed` был той же
   ошибкой: пустой адрес сверялся с текущей страницей и ставил паузу
   «поправьте Agent URL в базе «Роли»» — на пустом адресе нечего править.
   Отсутствие адреса называет `roleDeliveryUrl` с причиной; несвойственный
   адрес по-прежнему останавливает переход (защита контейнера).
3. **Квитанция прямого возврата сверяется с адресом доставки**, а не со
   строкой «Роли»: пустой URL совпадал бы с любой текущей страницей, и вкладка
   осталась бы не там, где чат адресата.
4. Релиз: ScriptCat 1.34.3 → 1.34.4 (пульт не менялся).

## Выпуск 1.34.0 (D-033) · ScriptCat 1.33.0

1. **Relay автоцикл стал исполняемым и включён по умолчанию:** старое значение `manual` мигрируется в `auto`, только если оно совпадает с прежним значением default; новый осознанный выбор `manual` сохраняется. Служба запускает фоновый диспетчер каждые 15 секунд и при пустой очереди сама передаёт планирующий ход Координатору.
2. **Автоматизация Firefox вынесена в WebExtension:** companion manager сопоставляет слот с контейнером Firefox по точному имени, переиспользует или создаёт Arena-вкладку в этом контейнере и не переносит cookies между сессиями.
3. **Режим Relay синхронизируется с ScriptCat:** автоцикл стартует без локального нажатия в каждой вкладке; при подключённом менеджере локальный ScriptCat не запускает параллельный самостоятельный план. Manual остаётся одношаговым. Менеджер оставляет admin-вкладку открытой, а созданные им неактивные worker-вкладки закрывает после трёх минут простоя.
4. **Безопасность контейнеров:** отсутствующий или неоднозначный контейнер — отказ с ошибкой, без автоматического создания новой identity или входа в чужой аккаунт.
5. **Предел проверки:** Firefox add-on проходит статические проверки и Node tests; реальный вход, AMO-подпись и полный цикл требуют smoke-проверки в целевом профиле Firefox.

Релиз: Relay 1.33.0 → 1.34.0; ScriptCat 1.32.0 → 1.33.0; Firefox add-on 0.1.0.

## Выпуск 1.33.0 (D-032) · ScriptCat 1.32.0

1. **Видно различие между hello и pull.** Снимок клиента отдельно показывает последнее распознавание, фактический опрос очереди и heartbeat. Пульт больше не считает один hello доказательством, что вкладка делает pull.
2. **Причина локально пропущенного pull попадает в журналы.** Если admin удерживает локальный `pending` или `expect`, ScriptCat показывает это в своём виджете и отправляет предупреждение в журнал Relay, не сбрасывая потенциально активную работу автоматически.
3. **Ошибки тика сохраняются.** Ошибка соединения/тика записывается в локальный журнал ScriptCat и (если служба доступна) в общий журнал пульта.
4. **История баннеров пульта не исчезает.** Последние 50 изменившихся сообщений доступны в раскрываемой «Истории сообщений пульта» после того, как временный баннер сменился.
5. **Релизные версии подняты:** Node Relay 1.32.0 → 1.33.0; ScriptCat 1.31.0 → 1.32.0.

## Выпуск 1.32.0 (D-031) · ScriptCat 1.31.0

1. **Admin-presence продлевается независимо от pull.** Каждая вкладка повторно отправляет `hello` раз в минуту, даже если локальный ход ожидает результата и не может отправлять `pull`. Это позволяет пульту восстановить список клиентов после перезапуска Node.
2. **Исправлен обход кеша hello.** Раньше `force: true` всё равно упирался во второй 10-минутный кеш, поэтому перезапущенная служба могла не увидеть уже опознанную вкладку. Принудительный heartbeat теперь действительно повторно регистрирует её.
3. **Релизные версии подняты:** Node Relay 1.31.0 → 1.32.0; ScriptCat 1.30.0 → 1.31.0.

## Выпуск 1.31.0 (D-030) · ScriptCat 1.30.0

1. **Автоадрес локального Relay.** При пустой настройке ScriptCat сам использует `http://127.0.0.1:8787`; ручное заполнение «Служба Relay» больше не требуется. `localhost` нормализуется в IPv4 loopback: Node слушает `0.0.0.0` (IPv4), тогда как `localhost` в Firefox может разрешиться в недоступный `::1`.
2. **Автопроба не ломает старый транспорт.** ScriptCat ищет стандартный Relay автоматически, но до успешного ответа не объявляет Node-путь подключённым и не прячет резервные функции. Пользовательский нестандартный адрес остаётся поддержан.
3. **Пульт больше не просит вводить localhost вручную.** Подсказки указывают автоадрес и одноразовое разрешение loopback в менеджере userscript.
4. **Релизные версии подняты:** Node Relay 1.30.0 → 1.31.0; ScriptCat 1.29.0 → 1.30.0.

## Выпуск 1.30.0 (D-029) · ScriptCat 1.29.0

1. **Исправлена ошибка выбора аккаунта между контейнерами.** `accountSeen` хранится через общее хранилище userscript и не является идентичностью текущей вкладки. Relay-клиент больше не использует этот кеш как запасной email для `hello`: он отправляет только email, прочитанный в текущем DOM Arena. Иначе вкладка admin могла зарегистрироваться под последним адресом рабочего контейнера (или наоборот), и пульт не считал её админской. Если email не прочитан или служба отказала в hello, причина теперь показывается в статусе виджета.
2. **Разрешён loopback-мост ScriptCat → Node Relay.** Добавлены `@connect localhost` и `@connect 127.0.0.1`; сетевые ошибки запроса больше не скрываются. Это дополнительная диагностика/разрешение, а не утверждение, что именно блокировка `@connect` вызвала наблюдавшийся сбой.
3. **Пульт показывает точный адрес подключения.** При отсутствии admin-сигнала он указывает origin открытого пульта для поля «Служба Relay» и напоминает проверить loopback-разрешение в менеджере userscript. Это отдельная настройка от выбранного профиля проекта в ScriptCat.
4. **Время журнала — московское.** События форматируются в `Europe/Moscow` с явной меткой «МСК», независимо от timezone компьютера.
5. **Релизные версии подняты:** Node Relay 1.29.0 → 1.30.0; ScriptCat 1.28.0 → 1.29.0. Перезапустите Node-службу и обновите/перезагрузите userscript-вкладки.

## Выпуск 1.29.0 (D-028) · ScriptCat 1.28.0

1. **Пульт различает три причины, почему шаг не начался:** админская вкладка не связана с этим Relay; вкладка связана, но локально на паузе; вкладка на связи и ждёт следующего опроса. ScriptCat сообщает состояние паузы и поддерживает presence heartbeat, не записывая повторные одинаковые строки в журнал.
2. **Локальная пауза остаётся предохранителем.** Вкладка на паузе объявляет себя пульту, но не забирает работу или команду Coordinator. Пульт не снимает safety-паузу молча: для продолжения нужно явное действие человека.
3. **Убираем дубли управления постепенно.** При активном соединении Node Relay из виджета ScriptCat скрыты старые «Шаг» и «Все вкладки»; вместо них есть ссылка «Пульт Relay». Если Relay временно недоступен, старые кнопки остаются как резерв. Оставлены локальный автоцикл и safety-пауза, подключения, агенты/provisioning, обратная связь и диагностика: у них пока нет полного эквивалента в Node-пульте.
4. **Подняты версии:** Node Relay 1.28.0 → 1.29.0; ScriptCat 1.27.0 → 1.28.0. Обновите bundle и перезапустите службу. Версия активной вкладки видна в пульте, если вкладка смогла связаться со службой.

## Выпуск 1.28.0 (D-027) · ScriptCat 1.27.0

1. **Пустая очередь запускает план, а не оставляет владельца с «выдач 0».** Нажатие «Шаг» в пульте ставит одноразовый запрос планирующего хода; admin-вкладка с совместимым ScriptCat передаёт его существующему `coordinatorStep/requestPlan`. Если открыта другая роль, ScriptCat переводит её на Coordinator. Нет активной миссии — это явно записывается в журнал.
2. **План Координатора попадает в очередь Node-службы.** Когда Coordinator выбрал Ready-карточку в Notion, userscript добавляет её в Relay queue; Node-служба назначает worker-слот, создаёт run и считает очередь завершённой после принятого отчёта. При отсутствии настройки службы сохраняется прежняя прямая доставка.
3. **Завершение миссии осталось явным.** Coordinator сдаёт `CF_COORDINATOR_RESULT` с `next:"done"`; старый проверенный Notion-гейт блокирует done при Submitted/Running/Ready/Blocked и передаёт чистую миссию Warden через `startReview`. Служба отражает `cycle.turn=warden`; только `CF_REVIEW_RESULT` с `verdict:"accept"` завершает цикл. `rework` возвращает Coordinator.
4. **Совместимость и обновление видны до выдачи.** Вкладка сообщает ScriptCat version в hello/pull/beat. Служба не выдаёт новую работу клиенту ниже минимальной версии; пульт показывает обнаруженную версию и ссылку на userscript. Требование — ScriptCat 1.27.0.
5. **Релизные версии подняты:** Node-пульт 1.27.0 → 1.28.0; userscript 1.26.0 → 1.27.0 (`@version` и runtime fallback синхронны). После обновления файлов Node-службу надо перезапустить; userscript обновить через менеджер либо raw URL, ссылка теперь в шапке пульта при несовместимой/неизвестной версии.

## Источник и граница provenance

Точный source repository, imported tree `fe8ec936…`, removal parent
`eecb687…`, MIT license и команда воспроизведения находятся только в
`tools/script-cat/UPSTREAM.md`. Это не operational target и не источник
продуктовых правил. Текущий target задаёт только профиль проекта: `owner/repo@branch` и связанные
источники, передаваемые профилем; в git транспорта проектных значений нет.

Regression fixtures сохраняют transport-семантику snapshot, но с 1.16.4
обезличены до `CASE-*`/`fixture-*`: прежние product names, repositories и card
prefixes не должны попадать ни в prompts, ни в comments/tests/contracts, где их
может принять за текущие Transport Maintainer.

## Выпуск 1.16.8 (внешний D-023)

Transport protocol остаётся 1.11; маркеры, профили, бюджеты, гейты и краткий регламент не

Три независимые причины, каждая из которых по отдельности глушила передачу:

- `appendQuestionBody` держал строку в «незавершённых телах» бессрочно. Пока запись тела
  живёт в очереди, строка намеренно не уходит приёмке (иначе агент получает обрезанный

  `C.questionBodyMaxTries` попыток; после края строка передаётся по тому, что лежит в базе,
  и отпускание записано в журнал ошибкой, а не тишиной;
- `flushQuestionBodies` не ловил исключение внутри петли — одна битая строка обрывала весь
  проход, и очередь остальных вопросов в этом цикле не обрабатывалась. Теперь каждая строка
  изолирована, ошибки считаются в ту же метрику попыток;
- передача лежала внутри `if (active)` (активная миссия). Миссия нужна, чтобы отфильтровать
  чужие строки и закрыть просроченные, а не как условие самой доставки; теперь сбой её
  чтения пишется в журнал, приёмка идёт без фильтра по миссии, а `closeExpired` остаётся
  под условием (без миссии закрывать нечем).

`projectBlockedText()` различает повреждённый профиль, вкладку без выбранного проекта и
снятый допуск (допуск снимается сам при смене Notion/Drive/GitHub-доступов в «Подключениях» —
это было второй половиной того же сбоя). Сторожа вопросов и ADR больше не снимаются допуском
вкладки, а если фоновый проход приглушён, в журнал идёт `feedback-pipeline-held` с конкретной
причиной и адресом, где её снять.

бандла (не на поиске подстрок) и красная на 1.16.7 по поведению: строка не передаётся без

### Будильник вкладок (D-006)

Квоты разложены по аккаунтам, но работа осталась по вкладкам: вкладка, увидев
задание для роли другого контейнера, уходила молча, и очередь ждала нажатия в
другой вкладке. Переход между контейнерами невозможен (`location.assign` его не
меняет), поэтому появилась просьба вместо перехода:

- кнопка **📣 Все вкладки** рядом с «Шаг» и «Включить» ставит общую отметку
  «работа есть, просыпайтесь» (окно 10 минут, не больше 30 подряд). Ничего не
  отправляет и не уводит страницу;
- откликается та вкладка, для чьей роли работа действительно есть (очередь или
  ожидание ответа). Чужие задания её не будят, поэтому три вкладки не начинают
  искать работу на пустом месте;
- задание чужой роли будит остальных само (`sendToRole`): после решения
  Координатора ход не ждёт нажатия;
- вкладка, ушедшая из-за чужого контейнера или лимита своего аккаунта, тоже
  ставит отметку — работа могла быть поставлена раньше, чем выяснилась причина;
- будильник — единственное исключение из «фон без нажатия ничего не делает»:
  он делает ровно то же, что нажатие «Шаг» в этой вкладке;
- если один аккаунт открыт в двух вкладках, шаг берёт только одна: вторая
  видит живую заявку и ждёт. Заявка — на аккаунт, поэтому соседний контейнер

  ожидание мержа не выглядит брошенным, а протухшая заявка (вкладку закрыли)
  не держит вторую дольше полутора минут;
- повторяющиеся причины («не на своём аккаунте», «аккаунт в лимите», «роль
  живёт в другой вкладке») будят остальных не чаще раза в 10 минут: иначе
  окно продлевалось бы каждые 15 секунд и ручной режим стал бы автоциклом;
- пауза и удержание остаются за Мастером: кнопка не снимает их, а говорит, что
  именно мешает;
- закрытую вкладку чужого контейнера будильник не открывает: это по-прежнему
  действие человека.

### Исправления перед мержем (та же 1.18.0)

Разбор собственной реализации нашёл три неверных места; выпуск не выходил, так
что нумерация не менялась:

- **Единица работы — вкладка в своём контейнере, а не «переход на другой
  аккаунт».** `location.assign` контейнер не меняет: из вкладки аккаунта A
  открыть роль аккаунта B нельзя — страница откроется под аккаунтом A. Поэтому
  поиск «другой роли другого аккаунта» из одной вкладки убран: ход идёт
  вкладками, каждая в своём контейнере, и общая очередь достаётся той, которая
  может её взять.
- **Лимит рабочего аккаунта не ставит паузу.** `pause` общая на все вкладки, и
  такая пауза остановила бы именно работу остальных аккаунтов. Вкладка молчит до
  сброса окна и говорит о причине один раз (в ручном «Шаге» — сразу).
  `accountsTick` возвращает вид остановки: `admin` (цикл стоит паузой),
  `worker` (роль не выдаётся, паузы нет), `unbound` (лимит без метки — прежняя
  пауза).
- **Вкладка в чужом контейнере пропускает шаг, а не ставит паузу.** Контейнер
  открывает человек; `navigateTo` такую роль тоже не открывает — её страница
  появилась бы под неверным аккаунтом.
- **Поиск не уводит вкладку к административным ролям** (Coordinator, Reviewer,
  Maintainer): у них свой контейнер.
- **Вопрос «работать нечем» отмечается при отправке, а не при сборке текста:**
  неотправленный план (капча, пауза, ожидание) больше не съедает вопрос на всё
  окно лимита. Мёртвый признак `q.once` в `askQuestion` убран — его никто не
  выставлял.
- **Раскладка ролей по аккаунтам называется в проверке подключений** (и
  отсутствие полей «Аккаунт»/«Доступность» в живой базе — тоже).
- Сайдбар разворачивается один раз на страницу, неудача чтения подписи
  кешируется 15 секундами вместо минуты.

## Установка

1. Импортировать файл профиля проекта (format `scriptcat-project-config`) через
   окно проектов ScriptCat; сам файл проект передаёт вне репозитория транспорта.
2. Убедиться, что активная вкладка показывает имя проекта, `owner/repo@branch`
   и Drive folder из импортированного профиля.
3. Сохранить Notion/GitHub/Gateway connections локально; secrets не входят в
   profile file.
4. Зарегистрировать Drive profile проекта только через Gateway flow.
5. Проверить подключения и вручную разрешить профиль. Автоцикл остаётся
   выключен до ручного включения.
6. Userscript устанавливает человек из принятого
   `tools/script-cat/relay.user.js` после сравнения SHA-256 с build report.
7. Старый browser profile можно хранить изолированно, но вкладка проекта не должна
   быть открыта под ним; ScriptCat fail-closed не подменяет отсутствующий профиль.

## Обновление

Transport Maintainer changes `src/**` only on a dedicated card. A source change
must bump both `@version` and `SCRIPT_VERSION`, add/update decision and regression
evidence, run `node tools/script-cat/build.mjs`, then complete the full gate.
Browser installation is never performed silently by repository tooling.

## Decision for the relay-wotr transport PR

No plain-semver bump is required when the only source changes are restoration of terminal newlines; this leaves the generated userscript byte-for-byte unchanged. Nor is a bump required for an embedded operational digest alone: the version bump gate is scoped to semantic `src/**` transport changes. Current transport version remains unchanged. This exception must not be used for behavior changes.

Bundle SHA-256 after regeneration: `4d10f303cbfd9672daf3917c2f6c6a9a9aaeb6b22a980c7bc4ed66b2fa9924ac`. The digest-only change does not require a plain-semver bump because the version gate checks `src/**` only.

## Transport-local CI gate

`.github/workflows/scriptcat.yml` is transport-owned, not part of the upstream docs mirror. It runs one aggregate check on pull requests and pushes to `main`, on GitHub-hosted runners with `contents: read`, no secrets and full-SHA-pinned actions. Checkout uses `fetch-depth: 0` and `persist-credentials: false`, so the zone preflight can see complete history and `origin/main` without repository write access. The workflow runs the full ScriptCat verification, installs `PyYAML==6.0.3` and validates its own YAML via `yaml.safe_load`, then invokes preflight. Making the aggregate check required in branch protection is a repository-owner setting.

Transport-only decision/journal and workflow details live here; since D-003 the
repository carries no project docs mirrors — foreign decisions appear in this
journal only as citations (D-002, D-003).
