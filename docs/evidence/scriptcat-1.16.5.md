## Scope

The release changes no delivery semantics: markers, role profiles, prompt budgets,
statuses, Notion and Drive contracts and the embedded regulation digest stay as they
were. It fixes one defect of the dispatch gate and the addressee rule that let it
reach the wrong owner.

- `27-review-answers.dispatchTask` re-reads the card immediately before the journal is
  created and now runs the same preflight as the first inspection, including the
  recipient `Зона записи` argument. Without that third argument the D-092
  `unownedPaths` gate lost its prose-zone exemption and rejected a card nobody had
  edited — the false «карточка изменилась перед выдачей» seen three times for
  `WOTR-1.1 B0 · Репетиция оракула`.
- A repeated-preflight rejection is announced with its own words
  (`повторная предполётная проверка: …`), which is how `40-heal-core.classifyPause`
  distinguishes the two reasons that share the `redispatch` pause kind: a transport
  defect goes to the Transport Maintainer, while an unchanged
  `предварительная проверка: …` first-inspection rejection remains a specification
  defect for the acceptance role. The genuine loop case (state, recipient or answer
  traces really changed) also stays with acceptance.
- The producer tags the same defect machine-side in `heal.defect`, so it enters the
  incident key and the Maintainer brief; `healMaintainerMax` and the following stop
  still bound the loop instead of restarting it.
- Both `@version` and the runtime `SCRIPT_VERSION` fallback moved to `1.16.5`
  together, as the version contract requires.

Two test expectations moved with this release for documented reasons:
`tests/relay-send-unregistered-smoke.mjs` pins the bundle version by number, and
`tests/relay-repo-visibility-smoke.mjs` pins the accepted specification revision of
the active mission, which became 1.2 when the specification was republished. The
latter assertion was already failing on `main` before this release started: it is a
stale expectation left by that republication, not a consequence of the ScriptCat
change, and it is corrected here.

Zone-scoped repository gate `node tools/script-cat/preflight.mjs --zone
"tools/script-cat/**, docs/**"` after `origin/main` was brought into the branch:
`behind`, `bundle`, `bundle-syntax`, `decisions` and `version`
(`1.16.4 → 1.16.5`) pass. Two checks stay red for the sandbox reasons recorded in the
handoff note — the clone is shallow, and the conflict-marker check reads every
tracked path as text and stops on `EISDIR` for the `engine/thirdparty/godot-cpp`
gitlink.

The `zone` check needs one environment caveat to be read correctly: with the default
`core.quotepath=true` it reports
`tools/script-cat/README-авторизация.md` as outside the zone, because git quotes the
non-ASCII path and the glob matcher compares the quoted form. Running the same gate
with `core.quotepath=false` gives `24 файлов, все в зоне`. This is a limitation of
`preflight.mjs`, not a foreign file in this change set; fixing the tool is transport
work outside this card.

## Release boundary

This evidence accepts the deterministic repository artifact and the bounded local
gates only. It does not claim browser installation, live dispatch, or acceptance of
the WOTR mission: installing `relay.user.js` in ScriptCat remains a manual owner
action after comparing SHA-256 with this record (D-027). The open acceptance row in
the Notion «Обратная связь» feed is left untouched on purpose — after this release it
is addressed to the Transport Maintainer, who receives the incident with the new
build number and version gate.
