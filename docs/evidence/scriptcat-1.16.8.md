# ScriptCat 1.16.8 · feedback-pipeline delivery evidence

Date: 2026-11-22

> Archive note (2026-11-22): this is release evidence kept as an operational record of Open BFME. The
> transport itself — source, bundle, tests, gates and future release notes — now lives in
> `Creative36711/relay-wotr`. Paths named below are read relative to that repository; this record is not
> edited, and no gate in this repository runs them.

Decision: `WOTR-D-023`. Trigger: the operator ran the loop manually (the `Шаг` button) and a row in
the «Обратная связь» base stayed `Ждёт` with an empty «Ответ» while `cfn-answer-queue` was empty and
the journal said nothing. Reading the 1.16.7 bundle showed three independent silence sources in the
transport itself, plus a panel message that named the wrong reason. The row is transport's debt;
"the answer will arrive with the next prompt" is not an admissible explanation.

Previous local release: `1.16.7`

## Scope

Delivery semantics are untouched: markers, role profiles, prompt budgets, statuses, the gate that
holds a turn while a question needs an answer, Notion and Drive contracts and the embedded
regulation digest stay as they were. `contracts/agent-protocol.json` gained no key and no outcome
name was removed. Nothing in the pause/hold model changed: `Шаг` still performs exactly one step and
auto-cycle still runs unattended.

- `tools/script-cat/src/24-feedback.js` — the hold on an unwritten full-text body is now bounded
  (`questionBodyHoldMs`, `questionBodyMaxTries`), `questionBodyEntry` carries `at`/`tries` across
  retries, written body text is compared through a whitespace-normalising `sameText`, the failure
  path counts attempts and logs the release as an error instead of `dbg`, and `flushQuestionBodies`
  isolates every row so one broken item cannot abort the pass. Adoption no longer sits inside
  `if (active)`: an unreadable active mission is reported (`questions-active-mission`) and the rows
  are handed over without the mission filter, while `closeExpired` stays conditional.
- `tools/script-cat/src/01-config.js` — `questionBodyHoldMs: 1800000`, `questionBodyMaxTries: 3`.
  `arenaResendMax` (a different mechanism) untouched.
- `tools/script-cat/src/02-profiles-core.js` — `projectBlockReason()` / `projectBlockedText()`:
  broken profile, tab without a selected project and revoked approval are three different
  sentences with three different fixes, shared by panel, step and journal.
- `tools/script-cat/src/24-feedback.js`, `src/25-legacy-adr.js` — the question and ADR watchdogs
  are no longer un-armed by the tab approval flag; `questionsWatchArmed()` / `decisionsWatchArmed()`
  expose the state, `armFeedbackWatch()` re-arms it, `noteFeedbackPipelineHeld()` names why the
  background pass was muted (throttled, `feedback-pipeline-held`).
- `tools/script-cat/src/28-cycle.js`, `src/06-pause-panel.js`, `src/29-boot.js` — `Шаг`,
  «Продолжить» and the muted boot path now use that wording instead of one generic line.
- Version bumped in lockstep (D-027): `@version 1.16.8` and the `SCRIPT_VERSION` fallback.

## Regression power of the new suite

`tools/script-cat/tests/relay-feedback-delivery-smoke.mjs` is built on the live bundle: it slices
`24-feedback`/`27-review-answers` blocks and runs them through `new Function` against a Notion and
ScriptCat-store model, so the assertions are behaviours, not string searches. The pinned version and
config checks were moved to the last section on purpose.

Controlled experiment — the 1.16.7 bundle was copied over `tools/script-cat/relay.user.js` and the
suite re-run unchanged:

```
AssertionError [ERR_ASSERTION]: сбой чтения миссии не снимает передачу с очереди
```

i.e. it fails on behaviour, at the first replayed incident. The integration suite
(`relay-feedback-integration.mjs`, new tail scenario «свежее удержание держит → просроченное
отпускает») fails on the same bundle with `AssertionError: после срока удержание гаснет`. Both are
green on 1.16.8. After the experiment the bundle was rebuilt from source, and `scriptcat:check`
confirms the tree/bundle match.

## Release boundary

No Notion, Drive, GitHub or Arena call was made by the release procedure itself: no artifact was
uploaded, no CI rerun was triggered, and all gate numbers above come from commands executed in this
sandbox against this tree.

Notion was touched twice in this working session and neither write belongs to the release:

- read-only lookups that produced the diagnosis. `search` for the base named «Обратная связь»:
  the name is crowded — three data sources carry it
  (`41e6f0cf-5705-817d-8029-000b2ef5c15c`, `abf2d533-04ec-4bbf-a261-ab21eb001e57`,
  `3d8efcea-19d9-48d3-8c3f-a4cfb7186f89`), so the first suspicion was plain mis-addressing. It is
  excluded in the repository: `tools/script-cat/wotr-project.json` sets `profile.questions` to
  `41e6f0cf-5705-817d-8029-000b2ef5c15c`, the same id in `docs/setup/notion-ids.md`, and the `search`
  result shows the stalled row is a child of exactly that data source — the row and the profile
  agree, so the stall is behavioural, not an addressing error.
  `query_database` filtered by `Статус = Ждёт` returned exactly that one row,
  `41f6f0cf-5705-8139-b90b-c69c24308819`, with empty «Ответ», empty «Что блокирует» and empty
  «Доставлено» — consistent with the code reading above, and not with a delivery that happened. A
  `get_page` of the mission row `41e6f0cf-5705-819a-a3ba-c15034fef51e` confirmed
  «Состояние = Активна» (the row the transport itself was reading). The base of missions was not
  enumerated, so a second `Активна`/`Возвращена` row — the one condition that makes
  `activeMission()` throw — is not excluded for that morning; the mission-lookup fix therefore
  covers both the confirmed failure mode and the unconfirmed one, and neither can stall the
  queue silently any more.
- three `update_page` calls on the «Роли» base, which wrote the «Зона записи» values mandated by
  `WOTR-D-022` (Upstream Integrator, Tactical Bridge Engineer, Strategic Core Engineer).

No card row, no status field and no terminal field was modified, and the mission row was read, not
written.
