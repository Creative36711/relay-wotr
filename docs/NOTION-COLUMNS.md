# Какие столбцы Notion удалять

Коротко: **Notion я не менял — ни одного столбца не удалял, не переименовывал и
не добавлял.** Всё, что ниже, это совет, что сделать руками вам. Удаляете вы.

Сверено с тем, что транспорт действительно читает (`relay/src/notion-db.mjs`) и
что объявлено его полем в контракте (`tools/script-cat/contracts/agent-protocol.json`,
блок `notionOwnership`). Всё, чего нет в этих двух местах, транспорту не нужно.

---

## База «Роли» — что транспорт читает

Живых столбцов семь. Остальные он не открывает вовсе.

| Столбец | Тип | Кто заполняет | Зачем |
|---|---|---|---|
| `Роль` | Title | Мастер / человек | имя роли, ключ пары (роль, слот) |
| `Функция` | Select | Мастер | административная роль или рабочая |
| `Статус` | Select | Мастер | фаза миссии; `Ждёт` — единственный блокер выдачи |
| `Agent URL` | URL | Мастер | **необязателен**: наследуется парой, пока у неё нет своего экземпляра |
| `Репозиторий` | URL | Мастер | куда агенту писать |
| `Agent Admin` | Checkbox | Мастер | живёт только в административном слоте |
| `Agent State` | Select | Мастер | допустима ли роль к работе |

## Что уже удалено и что это дало (29.11, проверено на живой базе)

`Agent Job ID` и `Agent Created At` удалены — и это **ломало создание агентов** до 1.23.0: Notion отклоняет весь запрос, если в нём есть отсутствующее свойство, поэтому вместе с ними терялись `Agent URL` и `Agent State`. Код исправлен (D-014): теперь пишутся только поля, которые есть в схеме. Удалять их было правильно — важно, что транспорт к этому готов.

**Поправка к прошлому совету.** В первой версии этого документа была таблица на удаление с `Аккаунт`, `Доступность` и `Гейт`. **Не удаляйте их:**

| Столбец | Почему остаётся |
|---|---|
| `Аккаунт` | читает ScriptCat: по нему считается квота аккаунта (D-004/D-005). `Доступность` — её пара, туда пишет транспорт |
| `Гейт` | читает ScriptCat (`role.gate`), условие приёмки в промпте |
| `Зона записи` | определяет, какие пути агент вправе править |
| `Агент State`, `Agent Admin` | без них provisioning и разделение админских ролей не работают |
| `Previous Agent URL` | пишется при замене агента; поле читается provisioning |

Остальные строки из второй таблицы ниже — по-прежнему к удалению, если они у вас появились.

## База «Роли» — что можно удалить

Ниже — то, что дублирует новую схему или не читается никем.

| Столбец | Почему удалять |
|---|---|
| `Agent Job ID` | переехало в лист «Экземпляры» (колонка `Job ID`), по роли больше не имеет смысла: у роли несколько агентов |
| `Agent Created At` | то же, переехало в «Экземпляры» → `Создан` |
| `Slots` / `Слот` | раскладка живёт в книге состояния и в листе «Слоты», в Notion она вторая копия и разъезжается |
| `Container` / `Контейнер` | то же: контейнер принадлежит слоту, а не роли |
| `Account` / `Аккаунт` | аккаунт — свойство слота (одна вкладка = один контейнер = один аккаунт) |
| `Quota` / `Квота` | квота считается по аккаунту в службе, в Notion это число никто не читает |
| `Max Per Role` | лимит роли — настройка `cycle.maxPerRole` в книге состояния, а не поле роли |
| `Priority` / `Приоритет` | порядок задаёт очередь, а не строка роли |
| `Last Seen` / `Последняя жизнь` | есть в «Экземплярах», у роли их несколько |
| любые `Notes 2`, `Copy of …`, `Temp` | следы копирования, транспорту не нужны |

Правило проверки, если сомневаетесь по столбцу: **если его нет в списке семи
строк выше — транспорт его не читает.** Удаление такого столбца ничего не
сломает. Обратное неверно: семь верхних удалять нельзя.

## База миссий (Requests) — не трогать

Её поля принадлежат Координатору и Warden'у, а не транспорту:
`Намерение`, `Инварианты`, `Acceptance`, `Scope`, `Кому`, `Sequence`, плюс
`Draft → Ready` и разбор `Submitted / Accepted / Rework`. Транспорт туда пишет
только прочтение и только свои поля (`Dispatch State`, `Run ID`,
`Output Drive File ID`, `Recipient Agent ID`, `Started At`, `Submitted At`,
`PR`, `Check`). Эти восемь — его, остальные не его; **ни один из них не удалять
по моему совету**, это зона Координатора.

## Чего в Notion быть не должно вовсе

Адреса агентов по контейнерам. Соблазн завести в «Ролях» столбец `Agent URL 2`
или `Agent URL (worker-1)` велик, и он же всё сломает: у роли столько адресов,
сколько контейнеров, и Notion не выражает это ни `url`, ни списком в `rich_text`.
Место для них — лист «Экземпляры» в книге состояния:

`Роль | Слот | Agent URL | Состояние | Создан | Job ID | Последняя жизнь | Заметка`

Строку туда пишет служба сама, когда вкладка сообщает адрес созданного агента.
Руками заполнять не нужно — и не надо: ручная строка со состоянием «создан» и
пустым адресом не считается готовой и всё равно потребует создания.

## Что делать по шагам

1. Открыть базу «Роли».
2. Удалить столбцы из второй таблицы. По одному, глядя, что не пропало ничего
   из первой.
3. Не трогать базу миссий.
4. Ничего не создавать: «Экземпляры» — это лист Google Sheets, а не база Notion.
5. Если после удаления карточка перестала выдаваться — дело не в удалении:
   проверьте `Статус` роли (не `Ждёт` ли она) и `Функция` (рабочая или
   административная).
