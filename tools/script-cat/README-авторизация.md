# Подключение Notion, Google Drive, GitHub и Gateway

[Главная](./README.md) · [Установка](./INSTALL.md) · [Инструкция агенту](./AGENT-SETUP.md) · [Ограничения и восстановление](./PORTABILITY.md)

Эта инструкция — для владельца. ScriptCat исполняет цикл в открытых вкладках Arena; профиль, подключения и секреты теперь настраиваются **в локальном пульте Relay**, не в интерфейсе ScriptCat. Агента можно попросить подготовить схему и сопровождать проверку по [AGENT-SETUP.md](./AGENT-SETUP.md), но токены и ключи ему не передавайте.

## Что подключается

| Сервис | Для чего | Где настраивается |
|---|---|---|
| Notion | Роли, миссии, карточки и обратная связь | UUID и ссылки — в JSON профиля пульта; токен — в поле секрета пульта |
| GitHub | Чтение репозитория, PR и предложений | `owner/repository`, ветки и маршруты — в профиле; токен чтения — по необходимости |
| Google Drive | Файлы заданий и журналы | Через собственный Drive Gateway |
| Drive Gateway | Веб-приложение Apps Script, работающее с Drive | Адрес `/exec` и проектный ключ — в пульте Relay |
| ntfy | Уведомления | Topic — в профиле; Access token — необязательный секрет в пульте |

**Подключения Arena для агентов и подключения userscript — разные вещи.** Коннектор Arena не подставляет токен в Relay, а токен Relay не даёт агенту доступа. Если агенту нужны внешние сервисы, отдельно включите коннекторы Arena и проверьте его доступ.

**Секреты вводит только владелец в доверенном локальном пульте.** Не отправляйте токены, пароли, коды подтверждения, Gateway key или содержимое `relay/project-config.json` в чат, репозиторий, issue или диагностику. Настройки хранятся локально в `relay/project-config.json`, который исключён из Git; защищайте файл и его резервные копии.

## 1. Notion: интеграция и доступ

1. Подготовьте четыре разные базы проекта: «Роли», «Миссии», «Запросы», «Обратная связь». Сверьте структуру с [NOTION-TEMPLATE.json](./NOTION-TEMPLATE.json); шаблон не содержит проектных записей или истории.
2. Если подходящей интеграции ещё нет, откройте [портал разработчика Notion](https://app.notion.com/developers/connections), выберите **Internal connections → Create a new connection** и нужное рабочее пространство. В Configuration включите **Read content**, **Update content**, **Insert content**.
3. Дайте интеграции доступ к четырём базам и нужным страницам. Включённый коннектор Arena сам по себе не выдаёт доступ этой интеграции.
4. Сохраните API token для ввода в локальном пульте. Токен Notion обычно начинается с `ntn_` или `secret_`. В JSON профиля его не добавляйте.
5. Подготовьте JSON метаданных профиля: четыре UUID data source, HTTPS-ссылки на страницу регламента и обратную связь, репозитории и маршруты ролей, имя папки Drive. Не подменяйте UUID data source ID представления из query-параметра Notion.

Подробности: [документация Notion](https://developers.notion.com/guides/get-started/internal-connections).

## 2. GitHub

1. Проверьте, что `owner/repository` и базовая ветка существуют. При необходимости включите отдельный GitHub-коннектор Arena для агентов.
2. Для публичного репозитория userscript обычно читает GitHub без токена. Для приватного репозитория используйте отдельный Fine-grained token с минимальными **Contents: Read-only** и **Pull requests: Read-only** разрешениями, сроком действия и доступом только к нужному репозиторию.
3. Сохраните токен локально и введите его в соответствующее поле профиля Relay. Он предназначен для чтения со стороны userscript; не вставляйте его в Git-команды и не передавайте агенту.

Подробности: [документация GitHub](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens).

## 3. Создайте собственный Drive Gateway

Gateway — код [drive-gateway.gs](./drive-gateway.gs), который владелец разворачивает как веб-приложение Google Apps Script. Он запускается с полномочиями владельца и запрашивает широкий доступ к его Google Drive. Проверьте код и аккаунт до выдачи разрешений.

1. В Apps Script создайте новый проект, замените файл кода содержимым `drive-gateway.gs` и манифестом [`appsscript.json`](./appsscript.json). Для существующего шлюза сначала сохраните его код и настройки; не перезаписывайте их вслепую.
2. В **Project Settings → Script Properties** задайте `CF_SETUP_PROJECT_ID` равным UUID профиля Relay и `CF_SETUP_PROJECT_FOLDER` равным имени папки Drive из профиля (например, `project-one`). Эти значения привязывают ключ Gateway к одному профилю и папке.
3. Запустите `setupProjectGateway` один раз. После проверки полномочий функция создаёт `Arena/<folder>/logs` и `Arena/<folder>/payloads`, регистрирует профиль и выпускает проектный ключ. Она не присоединяет существующую одноимённую папку и не должна повторно запускаться вслепую после частичной ошибки. Если в старом развёртывании уже есть `CF_GATEWAY_KEY` и реестр, не сбрасывайте и не заменяйте их при миграции: проектный ключ Relay — отдельное значение.
4. Разверните **Web app** от своего имени и со способом доступа, допускающим вызов из userscript. Для текущего протокола обычно нужен доступ **Anyone**; это открывает endpoint внешним запросам, поэтому публикуйте только проверенный код и не раскрывайте ключ. Если правила Google Workspace запрещают такой режим, остановитесь и уточните политику у администратора.
5. Скопируйте адрес вида `https://script.google.com/macros/s/…/exec` и проектный ключ в локальный пульт. Не используйте `/dev` и не передавайте общий ключ вместо ключа проекта.
6. При обновлении кода сохраните Script Properties, затем через **Deploy → Manage deployments → Edit → New version → Deploy** обновите действующее развёртывание. Перед обновлением общего шлюза проверьте клиентов, которые его используют.

Справка Google: [веб-приложения](https://developers.google.com/apps-script/guides/web), [Script Properties](https://developers.google.com/apps-script/guides/properties), [развёртывания](https://developers.google.com/apps-script/concepts/deployments).

## 4. Ввод настроек и проверка в Relay

1. Запустите постоянную (не `RELAY_DEMO=1`) службу Relay и откройте локальный пульт. Профиль с уже открытой Arena-вкладки импортируется в список без секретов; иначе нажмите «Новый профиль» или «Импорт JSON профиля» и загрузите secret-free JSON.
2. Выберите профиль. Введите Notion token, Drive Gateway URL `/exec` и Gateway key; GitHub token, ntfy topic и ntfy token — при необходимости. Нажмите «Сохранить профиль и подключения». Пустые поля секретов сохраняют прежние значения, а кнопка удаления очищает их явно.
3. Для проекта без активного допуска нажмите **«Сделать активным»**. Вкладки переключаются по одной, когда их локальная очередь и ожидание пусты; переключение не включает автоцикл и не удаляет состояние.
4. Откройте живую admin-вкладку Arena и нажмите **«Проверить и разрешить проект»** в пульте. Проверка использует локальные credentials, проверяет подключения и схему Notion только чтением, не исправляет схему и не запускает автоцикл. Запуск **«Шаг»** или **«Включить»** — отдельное решение владельца.

Проверка `ping` подтверждает ответ Gateway и совпадение зарегистрированного UUID/папки, но не доказывает все права записи, доступ к конкретному PR или успешность полного цикла. Проведите согласованный пилот на тестовых ресурсах; мок и локальные тесты не являются live smoke.

## Диагностика

- **Notion 401/403/404:** проверьте токен, доступ интеграции и четыре UUID data source.
- **GitHub 403/404:** проверьте репозиторий, доступ токена, разрешения, подтверждение организации и лимит API.
- **Gateway не подтверждает проект:** проверьте действующий `/exec`, версию deployment, UUID, имя папки и проектный ключ. Не запускайте регистрацию повторно, если предыдущая могла частично создать папки.
- **Профиль или credentials не синхронизировались:** остановите цикл, не очищайте очередь/ожидание, проверьте активный профиль и `relay/project-config.json`; повторите проверку после восстановления службы.
